# AGENTS.md

Agent-facing instructions for this repository: a curated set of five UI/UX & writing skills, vendored byte-for-byte from upstream. Skill bodies are the sources of truth — do not edit them. The routing below decides **which** skill runs for a given request; follow it before opening any SKILL.md.

## Skills

| Folder ($SKILL) | Trigger |
|---|---|
| `skills/design-taste-frontend` | Build or restyle a **new** landing page, marketing/portfolio/one-pager; treat "looks generic / AI-made / not premium" complaints on public pages as this skill's trigger |
| `skills/impeccable` | Improve, audit, critique, polish, harden, animate, or iterate an **existing** UI (product screens, dashboards, settings, components) via its 24 commands |
| `skills/ui-ux-pro-max` | Look up design conventions & data (styles, palettes, font pairings, UX guidelines, stack specifics) before or during any UI work |
| `skills/frontend-design` | Universal aesthetic principles for any fresh UI/art direction; no runtime — read the prose as a lens, not a procedure |
| `skills/no-ai-slop` | Any copywriting or text editing task (UI copy, README, docs, drafts); detect or remove AI-slop patterns |

## Routing rules

1. **Landing/marketing from scratch or restyle** → `design-taste-frontend` (its own run, scripts, and screenshot loop). Not `impeccable`, which assumes an incumbent implementation.
2. **Refining/auditing existing product UI** → `impeccable`. Not `design-taste-frontend`, whose art-direction dealing would override the incumbent identity.
3. **App screens (dashboards, admin, settings)** → `design-taste-frontend`'s `references/app-screens.md`, then `impeccable` for polish.
4. **Before choosing styles/typography from nothing** → search `ui-ux-pro-max`'s data once for conventions; it reports options, it does not make the final decision — taste skills do.
5. **Principles check anytime** → `frontend-design` (cheap: ~9 KB, but raises quality floor decisions such as typography and motion restraint).
6. **Any user-facing copy or locale text** → run through `no-ai-slop` before shipping.

Anti-overlap guard: do **not** chain two routing-equivalent skills on the same artifact (e.g. `design-taste-frontend` full run + `impeccable` shape on the same page in one session). Use `ui-ux-pro-max` + `frontend-design` as supporting inputs only — they never "own" the build.

## Environment notes

- `design-taste-frontend` scripts need Node 22+ and Chrome/Edge/Chromium; run from the project root so working files land in `.taste-skill/` there. No API keys; `assets.mjs` needs network access.
- `impeccable` resolves its engine on first run through its own launcher (`scripts/impeccable`); the binary self-downloads to `~/.impeccable/bin/`. If the launcher fails, say so to the user, then read the project's existing `PRODUCT.md`/`DESIGN.md` directly and continue without inventing missing context.
- `ui-ux-pro-max` runs its search scripts offline against bundled CSV data.
- `frontend-design` ships its own `LICENSE.txt`; keep it when copying the folder.
- When working in a project that has a `DESIGN.md`/`PRODUCT.md` generated by `impeccable`, honor it as the pinned design context for that project.

## Update policy

Upstream sync is manual-review-only. Each skill's provenance commit is recorded in `README.md`; when updating, diff the vendored folder against the upstream commit and review every change before merging. Never pull these folders automatically.
